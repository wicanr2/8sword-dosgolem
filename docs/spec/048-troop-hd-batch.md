# 048：部隊與怪物的批次 HD 素材

素材製作與批次接入：限定 CONFORMED。範圍為 MAN01 至 MAN25 的圖片替換與共用機制抽驗，不宣稱全遊戲 HD 或逐隻自然遭遇驗收。

使用者於2026-10-26指定：未正式接入的怪物先繪製HD圖片；相同繪圖機制由前幾隻怪物與部隊抽驗成功即可，不逐隻重走正常玩家流程。需要補圖形驗證時，允許修改記憶體狀態。這項授權只用於可重播的呈現驗證，正式遊戲邏輯、原始存檔及亂數不因此修改。

## 來源與範圍

- 沿完整圖形盤點`all-graphics-catalog-r4/catalog.json`及既有019／023至029／041／042的共用繪圖機制。MAN01至MAN25共100筆姿勢，批次開始時正式登錄20筆，缺20組、80筆。
- MAN27的四筆太極圖用途仍未知，與MAN.AY的主角／圖示分開，不當作缺少的第26種怪物。
- 來源檔、解碼記錄、原始色碼及遮罩由既有盤點雜湊固定。資產名稱用MAN資源編號，不猜官方兵種名稱。
- 風格沿已確認的明亮中國古風與原版主要配色。原版決定物種、服裝輪廓、裝備數量、朝向及四個動作；HD只提高畫面細節。

## 製作與保存

[準備工具](../../tools/prepare-troop-hd-batch.py)在固定Pillow11.3.0 Docker使用`--project <唯讀專案> --out <新研究目錄>`，產生缺圖清單、每姿勢原圖、四姿勢參考與完整提示。研究輸出沿既有`graphics-first/battle-r1/troops-hd-bulk-r1`，不另開同職責根目錄。

使用內建image_gen，一組資源產生一張透明2×2四姿勢圖集。每張保存來源、提示、工具、輸出路徑及SHA。已存在的五組HD不重畫；左右鏡射由共用機制處理，不另外生成另一套角色設計。

圖像先完成並保存在本機。逐隻正常遭遇、反覆走地圖、所有姿勢GUI截圖不列為完成圖片的條件。技術整理只核對檔案、透明度、圖格與來源對應；共同機制需要新抽樣時可用明示的記憶體控制，保留原版地址、輸入及狀態紀錄，不將其標成自然玩家路徑或玩法parity。

正式接入仍保存來源雜湊、素材清單與安全回退。相同格式與機制沿既有已驗契約批次處理，不為每隻再建立一份逆向規格。真正新增的格式、遮罩或玩法行為另行查證。生成原圖與原版資料留workplace；README只收已授權的總覽，完整素材不因完成製作就自動公開散布。

## 批次接入契約

狀態：限定 CONFORMED，先經下列證據審查達READY再實作。用途為原有四姿勢及兩向的HD替換，不新增兵種、數值、掛點或存檔欄位。原版資料及呼叫ABI沿019／023／036／042，原始來源版本由上方完整清單固定。

- 每組獨立`troop-manXX.json`，四筆記錄固定3304 bytes，來源檔共13216 bytes，開頭為寬11 bytes、高50。來源全檔SHA以固定清單核對。六區塊鏡射依042，識別前2204 bytes與完整3304 bytes各自核對。
- 透明圖集按收據的四個圖格切為四張PNG，完整圖集不改。取樣框取alpha大於3的外框，沿既有`sampleBattleActor`生成264×300預乘快取。原版遮罩僅移除位於底部、獨立且扁平的黑／灰地影元件，再取外框；此為顯示位置近似，保留完整角色，不宣稱原版圖像逐像素相同。
- 每筆原向與鏡射各有全域圖像和戰場別名，兩者共用同一不可變快取。新增識別160至479固定依20組、四記錄、兩向及兩用途排序。`ByNative`指向全域識別，背景頁繪圖才選戰場別名，F2沿既有非戰場背景契約。原有0至155保持。
- 每組須先核對來源、樣式、四PNG、取樣／目的框、兩向六平面指紋、快取SHA及識別衝突，再一次提交。缺少清單保留原圖；一組損壞僅回退該組，其餘19組、原有5組、字型與效果保持。不從JSON接受額外檔案路徑、任意ID、原生位址或鏡射算法。
- 原始資料至呈現鏈沿`Graphics.beginSource`、六平面完整核對、原版背景頁、角色快取及既有交易提交；存檔保持原版格式。新圖不需要逐隻正常遭遇；抽驗原向／鏡射、背景還原、F2、故障與字型。必要時用明示記憶體測試狀態並保留前後值，與既有正常F1／F2／F7收據分開標示。

準備與定位工具為[prepare-hd-troops.py](../../tools/prepare-hd-troops.py)，在固定Pillow容器指定`--project`、`--base` r48、`--batch`已完成圖集、`--out`新候選與`--review`新研究目錄。清單及預覽先保存在既有`battle-r1`，正式匯入及抽樣結果另追加本節。

證據審查：`troops-registration-r1/registration.json`的SHA為`5a3476243b2e709a8915d262e95829e19a52f37599a027b0b32b8757e3bca18c`，Pillow11.3.0由既有獨立Python取樣器產生160份兩向RGBA快取。候選`assets-troops-candidate-r1`共344檔，223舊檔保持。已抽看MAN02／03／08／20／25的四姿勢定位，包含人形、灰色幽靈及大型龍形。原版25組、四筆、兩向共200份前2204-byte指紋與完整六區塊指紋均無重複。每組JSON的SHA由程式固定，來源SHA、圖像SHA與框位不能由重寫JSON自行更換；ID由固定組序計算，不接受清單注入。此審查足以沿既有機制實作，不要求逐隻自然遭遇。

## 正式接入與限定驗收

正式素材為`workplace/player/assets-painted-r49`，344檔，保留r48全部223檔。新增20組80筆，每筆兩向，共160份快取及160個戰場別名；同一方向的軍隊與戰場用途共用快取，不複製PNG。`build-troops-r1`保存113份輸入、52份套件正式來源、Go1.24.13、七程式與來源archive，已提升至本機正式入口。舊建置、素材與八份固定核心保持。

本節取代[040的早期MAN02接入閘門](040-battle-swordsman-poses.md)。固定來源仍為同一`MAN02.EGG`與四個檔案偏移；改用048新圖及使用者明確批准的共用機制／受控呈現抽驗。040舊稿、定位限制與未知動作語意保留，不因本次接入改寫為已走自然遭遇。

[載入器](../../internal/eightsword/troops.go)及[測試](../../internal/eightsword/troops_test.go)沿上述契約。`troops-tests-r1.log`的三項父測試於60.626秒通過，核對160份快取逐byte同獨立Python取樣，完整原版六區塊、兩向、用途別名及所有舊材質／角色／字型／效果保持。五項故障抽樣涵蓋壞清單、最後PNG、原版來源、缺清單及識別衝突；失敗不留下部分角色，不影響其餘組。

受控呈現先以普通輸入走啟動、新遊戲、地圖、F1及F2，再於可丟棄的客體記憶體呼叫真正原版常式。RAM `8000:0000`作64004-byte來源緩衝，原始內容另存，結束以defer恢復；DS設`0AA8`，控制欄位`DS:7484`、`DS:748A`及執行期`14D2:0196`明示並恢復。原版`14D2:099C`繪製固定GRO02前後頁，再呼叫`14D2:04F2`或`14D2:0626`，不改正式程式或存檔。這些都是dosgolem執行期位址，不與IDA線性位址混稱。

`troops-controlled-r1/receipt.json`共12案：MAN02／MAN08／MAN20各兩向、兩入口。每案2304000像素全幅同已驗背景與獨立角色快取的合成，共27648000像素；Frame前後完整客體保持。持刀兵鏡射與龍形完整圖已抽看。GRO02 fixture沿既有Huffman decoder，來源SHA `9e0182e0a576d62564ffcdccc6b9484bd0ff94e4f545ca43045f9aa1c1c45e4a`、解碼SHA `b2262e970d5525826db47e9507787f9f3daddb2e00394934c728dc5d0ee8f763`，工具與方法見`troops-registration-r1/draw-fixture.json`。此為明示受控呈現，不稱自然遭遇、規則或RNG對拍。

正常GUI `player/gui/troops-save-r3`有305／224次Draw、51／26次變化，兩張完整接觸表及Noto主選單已看。三字型、偏好恢復、F1／F2往返、自然問題框選否與F7存退冷讀通過。2987-byte人物檔與存後／冷讀RAM均同SHA `29dd62aed5918ac7ef9dcd4020a90d8a8ff84355bcd9405ded3432116b1a2359`，正常DOS退出0。存讀RAM由零步只讀檢視取得，不用快照取代冷讀。

首次GUI r1誤設`-font noto`，在冷啟動覆寫草書偏好；r2又複製該覆寫後設定，兩次冷讀皆被驗證器拒絕。來源程式與015確認後，改用全新隔離設定、移除強制字型，r3同一程式與素材乾淨重跑通過。兩個失敗保留為驗證設定問題，未改遊戲或放寬檢查。
