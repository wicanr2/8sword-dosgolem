# 034：募兵建築的手繪背景

狀態：限定 CONFORMED。使用者已選定手繪城門，來源審查、正式接入與下列正常路段驗收通過。本項承接 [004](004-hd-bitmap-presentation.md)的四平面圖像觀測，只處理 `LIVE2.AY`；募兵規則、其他建築及音樂不在此規格內。研究入口為 `workplace/probe-20261023/graphics-first/map-interaction-r1/`。

## 已確認的畫面與來源

- 使用者於 2026-10-25 明確選「採用這版手繪城門」。[定稿 PNG](../images/recruitment-gate-approved-r1.png)、[完整提示](../images/recruitment-gate-approved-r1.prompt.txt)及[批准紀錄](../images/recruitment-gate-approved-r1.json)同次保存，PNG SHA `7aa67f8975843e91e0a393863ba08bb77582fd4ab62ee10fad059bebcd5b61ab`，原圖 1877×838、不透明 RGB。只能保存至既有私人倉庫，沒有公開散布權。
- 原版 `LIVE2.AY` 為 11480 bytes，SHA `b854b04f3b0d3620adc37e3adb498cbe3ae710f007766695f40f4065ebde32eb`。沿已驗壓縮樹解碼器得到 22404 bytes，SHA `edf6a0cc7dc13fbd054049bcb9bec91e1386c0c8b141174da376499854cb5978`。表頭兩個 word 為 56、100，後接四個 5600-byte 平面，沒有第五組或遮罩。
- `live2-comparison-r1.json` 核對解碼圖與正常執行的 `live-r1/11-north-two-native.png` 原生 `(8,12)-(456,112)` 全部 44800 個像素相同。樣稿只在對應 HD `(24,72)-(1368,672)` 放入定稿，框外文字、數字及側欄逐 RGB 相同。這是合成樣稿，不是正式接入證據。
- 原版正常移動後載入 `live2.ay` 並顯示民兵募兵提示，Esc 返回；空搜尋與募兵提示的場景分類仍為 map。本項不依這個粗分類決定畫面，也不修改它。實際顯示以固定圖像來源與已驗寫入所有權為準。

## 原版執行期證據

`probe-source-r4.go` 沿正常冷啟動、新遊戲與 `commands-r2.txt` 的普通按鍵，對既有四平面入口加只讀擷取。入口為 dosgolem 執行期 `14D2:099C`，返回 `14D2:0A6F`；212 個入口 bytes 必須全同固定 `PAM.AY` 檔案偏移 `0x15A2C` 起的原 bytes，返回必須為 `CB`。這裡的執行期段位址、PAM 檔案偏移與來源 SHA 各自保留，不當成同一種位址。

首筆取得來源 `6000:0000`、目的 `A000`、x byte=1、y=12，完整來源同解碼 SHA。`live2-runtime-source-audit-r1.json` 核對三次實際重繪的返回各 44800 個色碼全同獨立四平面公式。開／關觀測各 472 次 Frame 純度通過；完整客體 SHA `5c439e3433fa633428bf4130a15fff7ced55bfd78ba6f0398b431f7cf3dc23a3`、PCM SHA `2c0f83c32639d4d279f50854008d07f5399de573bd26594cb777427d52cb6abf`、31 工作檔及輸入／文字／I/O／EXEC 事件相同，也同上一輪未加掛點探針。工具版本與探針 SHA 同收據。這足以支持圖像接入，不延伸為募兵規則或亂數驗收。

## 接入契約

1. 新增可選 `recruitment-building.json` schema 1，沿現有獨立資產群載入模式。固定來源、解碼 SHA、已批准圖 SHA、尺寸與風格識別，拒絕未知欄位及尾隨 JSON。清單最多 64 KiB，圖檔最多 8 MiB、1877×838，普通檔案且不透明。
2. 核對原版 `LIVE2.AY` 後，將既有四平面指紋登錄為獨立材質 ID 112，來源索引 111。NativeWidth=448、NativeHeight=100，沿既有雙線性取樣快取 1344×600；PNG bytes 不變，不裁切、不改比例。ID 108–111 是既有 CHOI 四姿態，不能重用。新組在既有群組之後載入，衝突時只拒絕新組。
3. 只由既有 `099C` 及圖像所有權機制覆繪，不加新 CPU 掛點、不改原版繪圖。搬移、同值寫入、清除、文字及未知來源沿 004 的失效機制，不憑建築類型或募兵數字猜場景。
4. 任一新資產驗證失敗時，只停用這組建築並記錄 `recruitment_building_error`，原版建築、Noto、其他 HD、輸入及音樂保持。舊素材組沒有清單時沿既有行為。
5. 匯入從 r33 的 158 檔建立新組，全部舊檔逐 SHA 保持，新增圖、提示、清單與來源收據。獨立乾淨重建須相同。完整素材組與原版檔留本機。

## 驗收與完成條件

- 正常冷啟動、F6、人物頁、自然遇敵原版選否及移動到建築，不讀快照或注入位置。保存新組／舊組／真壞圖三組相同輸入，完整客體、PCM、工作檔及事件必須相同。
- 實際建築幀由定稿 PNG 獨立重建 1344×600，逐 RGB 核對。文字與框外同控制組；未出現建築的幀相同。壞圖應完整同舊組而保留字型。
- 真正視窗完成進入、三字型、Esc 返回、F1／F2 及 F7 真存退讀。至少抽樣一份建築 actual Draw，不能只用無頭圖或合成樣稿；連續幀檢查殘圖與原圖閃現。
- 若測試成功募兵，只用原版數字輸入與 Enter，保留實際前後狀態，不自行推導費用、兵種或上限規則。原版金額、兵力及亂數規則不由此升格為 parity。
- 本項通過只閉合這份建築背景與已驗路段。整體 HD、其他建築、部隊動作及其餘曲目繼續保留原目標。
