## 初期正常玩家路徑與缺口

1. 沿 019 的固定 DOS 時鐘、新遊戲、首場自然遭遇及普通按鍵。原版手冊 `掃描0006.jpg` 印頁 7 的方向鍵、`掃描0007.jpg` 印頁 9 的戰鬥游標／Enter／空白鍵／Esc 是操作依據。不載快照、不直接進場、不注入兵力或位置。
2. `man21-control-r1` 保留既有按鍵，原最後三秒之後只追加五秒等待，896 次來源、22 種記錄，MAN21 仍只有首筆，最後已到戰鬥結果。不能將「較久等待」視為完整動作覆蓋。
3. `man21-control-r2` 記錄向右三步的畫面。第二步圓形游標位於 MAN21，第三步移到空位；r3 依這份實際畫面在第二步選定後按 Enter。兩次皆正常返回戰鬥結果，但 MAN21 仍只觀察到首筆。沒有據此猜測攻擊、命中或傷害規則。
4. 單筆首次完整幀觀測原先會在另一來源返回時清掉待取樣記錄，r2 改為保留最近一次已完成 MAN21 返回。這只修只讀探針，不改正式呈現或客體；首筆實際畫面仍須核對，不能由觀測器旗標宣稱動作出現。
5. 經兩次操作仍未出現其他姿勢，回到 GUI 還原與 IDA 路由，停止追加盲目按鍵。`ida-man21-dispatch-r1.json` 由正式 PAM.i64 唯讀副本、IDA 9.4 匯出四個既有繪圖 helper 的直接呼叫端，不重做頁與遮罩 RE。

## 動畫入口定位

來源為原版 `PAM.AY` SHA `83e32f132e808d70ac7e170aa1c0019eb4c579b9c785f2cbaf0d3e00af28d6c0`。以下各位址基準分開列示，保留原始函式名與運算元，不改正式資料庫。

| 原始定位 | 已證實的指令；語意限制 |
|---|---|
| IDA MZ 線性 `sub_210CE`，0x210CE..0x21167；檔案偏移 0x1253E | 依參數及 `[bx+6FC2h]` 找來源；檢查 `[si+5702h]`，由 `[si+705Ah/705Ch]` 送出首筆。欄位的正式名稱未知 |
| IDA MZ 線性 `sub_23A42`，0x23A42..0x23AFC；檔案偏移 0x14EB2；PAM overlay 執行期線性 0x14B42 | 先檢查 `[bx+5700h]`，非零才按 0CE8h 步長輪播 1／2／3／0，最後視參數還原。與首筆檢查的是不同 word；目前只將它稱為動畫前置檢查，不猜欄位語意 |

IDA MZ 起點 0x10000，已知 PAM overlay 載入／重定位段 0110，所以本次執行期線性為 IDA 值減 EF00h；此換算只用於已確認的 PAM，不套其他程式。新入口的完整 bytes 含 MZ 重定位項，必須按原 relocation table 加 0110h 後再比對正常記憶體。r4 探針直接比較未重定位 bytes，因此來源衛式拒絕；不作遊戲缺陷或該入口不可用的證據。正常欄位與參數觀測接續 r5。

### r5 正常欄位觀測

`animation-fingerprint.json` 已依四個原 MZ relocation 項修正比較值，186-byte 動畫入口的正常記憶體及預期重定位 SHA 皆為 `5bacbcc1b05760041076991732d21c1602d9bd003d0fba0a4d124df57912a2e9`。IDA 正式 DB SHA `a9089db0a8921c732a96f9d4082020f7d3575c98af0925c2c1fb91c3c7ad21ac` 未改，工具沿既有 py312-v1 image SHA `4ac62de83339c215bab10e455cee3a22d9c6efed9fd0d8ed0f068327b83a06ab`。

正常執行期 DS=1E88h，DS:5700h 起六組原始 word 值為 `(16,32)`、`(6,10)`、`(11,30)`、`(21,40)`、`(0,0)`、`(0,0)`；DS:705Ah 的來源指標依次對應 MAN16／06／11／21。MAN21 位於索引 3，第一個 word 非零，故本路段沒有被該前置檢查擋住。實際 27 次輪播參數索引分別是 0 十次、1 九次、2 八次，沒有索引 3。這證明未呼叫該位置，不證明後排、射程、行動順序或遊戲規則的原因。
