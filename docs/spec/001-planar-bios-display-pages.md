# 001：BIOS 低解析度平面顯示頁

狀態：限定 CONFORMED。2026-10-23 由黑畫面研究起草，完成來源、呼叫與頁內容審查後達 READY，再完成下列修正版驗收。範圍限 0Dh／0Eh 的 BIOS 頁切換與已列原版路段。

## 證據與問題

- 原始輸入與雜湊見 [研究紀錄](../../RESEARCH-LOG.md)。dosgolem 基線為 `f79eab6db8c64a524a06535e53e5d32b0bbcf7c8`。
- 從未修改的 `PREDELLA.EXE` 正常選 VGA、AdLib 後，原版自行 EXEC `PAM.AY`。在第 120961932、120962085 步呼叫 `INT 10h`，AX 均為 `0501`。觀測點為執行期 `CS:decoded-IP=14D2:01A7`，IP 已越過 INT 指令；此值不是檔案偏移或 IDA 位址。
- `workplace/probe-20261023/page-calls/` 的研究工具續跑至 125000000 步，記錄上述呼叫。工具只觀測原有中斷掛勾，沒有修改遊戲記憶體或顯示起點。
- 199999999 步快照中，平面位移 `0x0000` 的 640×200 圖面全零；位移 `0x4000` 有 24480 個非零像素，可讀到繼續／新遊戲選單。這是診斷用頁檢視，不能冒稱玩家已看見選單。
- 基線 `internal/dos/bios.go` 的 AH=05h 為空操作；`0040:004C` 仍為文字模式的 `0x1000`，`0040:004E`、`0040:0062`、CRTC 顯示起點均為 0。

## 平台契約來源

本節採用固定提交 DOSBox-X `5fcf624b` 的既有 BIOS 契約，不逆向遊戲來重證硬體：

- [顯示頁切換](https://github.com/joncampbell123/dosbox-x/blob/5fcf624b/src/ints/int10_char.cpp)：AH=05h 依頁大小更新 BDA 起點、CRTC 起點及目前頁。
- [模式表](https://github.com/joncampbell123/dosbox-x/blob/5fcf624b/src/ints/int10_modes.cpp)：0Dh 為 320×200、每平面每頁 `0x2000` bytes、8 頁；0Eh 為 640×200、每頁 `0x4000` bytes、4 頁。

只參考公開介面及模式參數，不複製該 GPL 實作。本案修改保存為獨立補丁，不能直接改共用 dosgolem 工作樹。

## 實作範圍

1. 設模式時，0Dh／0Eh 的 BDA 頁大小依上表初始化。模式切換重設 BDA 目前頁與起點為 0，與 VGA 模式重設的零起點一致。
2. AH=05h 在 0Dh／0Eh 接受合法頁號，更新 BDA `0040:004E` 起點及 `0040:0062` 頁號，將頁起點寫入 CRTC 0Ch／0Dh。這兩種模式的既有 CRTC 為 byte addressing。
3. AH=0Fh 的 BH 讀回 BDA 目前頁，不再固定回 0。
4. 選頁不改平面內容、遊戲狀態、亂數或存檔。沒有為本作加入專用位址或旗標。
5. 非法頁號採忽略的實作邊界政策，不宣稱此為所有實機 BIOS 的行為。其他模式的 AH=05h、其他模式的頁大小、非標準 CRTC 定址不在本切片範圍。

## 驗收

- 0Dh／0Eh 分別驗頁大小、最後合法頁、非法頁不改狀態、AH=0Fh 回報、切回第 0 頁及重新設模式。
- 不同頁放不同已知像素，切頁後讀正常畫面，證明換的是顯示起點且沒有複製或清除 VRAM。
- 保存與讀回快照後，BDA 與可見頁一致。
- 執行 dos 與 machine 套件測試。從修改前的 79999999 步原版快照重播，讓原版自然呼叫 AH=05h；不能手動把錯誤快照切到第 1 頁代替修正版收據。
- 修正版的玩家可見選單須與同狀態診斷頁內容一致。DOSBox-X 截圖另外標為輔助基準，不冒充 dosgolem 收據。

完成聲明只涵蓋此 BIOS 缺口與實際重播路段，不涵蓋整個遊戲、HD 或全曲音樂。

## 驗收結果

- 補丁為 [tools/dosgolem-planar-pages.patch](../../tools/dosgolem-planar-pages.patch)，SHA-256 `962388ca6093b258f9fcc1171c9d9fc9a1949670870172f5c62fd93b21e4106a`；只套用本案隔離副本。
- 修改前，新增契約測試在兩個模式的頁大小及快照可見頁失敗，證明測試能拒絕原缺口。修改後 dos、machine、state、oracle 四個套件全部通過；原始 log 在 `workplace/probe-20261023/validation/tests.log`。
- 原版 79999999 步快照正常續跑至 125000000 步，讓原版自行切頁，畫面與未修改快照的診斷第 1 頁逐 RGB 像素相同。從零冷啟動、相同兩個 BIOS 按鍵亦得到相同畫面，兩項差異皆為 0。
- 修正版快照的 BDA 頁號為 1、頁大小與頁起點皆為 `0x4000`，CRTC 起點同為 `0x4000`。未以修改 RAM 或手動切頁修補原版快照。
- 已沿原版輸入進入新遊戲、移動、開 F7 存檔及冷啟動讀回。這些是 dosgolem 執行原版的路段驗證，尚無本案前端 GUI 或 HD 覆繪。
- 數值收據及來源保護由 [tools/audit.py](../../tools/audit.py)核對，入口為 `bash tools/research.sh audit`。讀回遊戲畫面有主角區域的動畫相位差異，未稱整幅畫面完全一致。
